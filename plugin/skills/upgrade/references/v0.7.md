# v0.7.0 — ship, release, the pre-push backstop, convention rules

## Heads-up: the pre-push backstop now exists

The first `bunx dobby up` after the jump installs a git `pre-push` hook into the repo's common hooks dir (covers every worktree, honors `core.hooksPath`). It re-runs the gate before anything leaves the machine; a gate cache keyed on the tree makes the after-a-green-`ship` path instant, so only the FIRST push after the upgrade may run the full gate once. `git push --no-verify` bypasses it deliberately. Nothing to configure — tell the user it now exists and what the bypass is.

## Heads-up: the gate carries convention rules now

`dobby check` now enforces house conventions in tiers — native Biome rules, filesystem checks, and GritQL plugins on the react preset path — all capability-gated to the stack. Step 4's gate run is where they first fire on this repo; expect findings on a previously-green tree and treat each as a real fix-vs-suppress call, never bulk-silence.

## Action: delete local skills the kit absorbed

If the repo carries project skills duplicating what the kit now owns — a `.claude/skills/release/` (absorbed by `/dobby:release` + the `release` config key), run/dev wrapper skills (absorbed by `dobby up`/`dev`) — list them and confirm with the user before deleting. Leave unrelated project skills alone.

## Action: declare the release target (publishing repos only)

`dobby release` exists only when `dobby.config.json` declares the `release` key — an undeclared target hides the command entirely. If this repo publishes anything (an npm package, a Homebrew cask), offer to declare it; the per-channel keys (npm: `dir`/`lockstep`/`surfaces`/`smoke` · homebrew-cask: `tap`/`cask`/`lockstep` + optional `notaryProfile` for Developer ID notarization) are documented in `/dobby:release`'s prerequisites table. A repo that publishes nothing skips this section.

## Awareness: the new command surface

The skills now delegate their mechanics to `dobby ship`, `pr watch`, `review fetch|apply`, `state`, `build-plan`, `repro`, `tracker`/`claim`/`goal parse`, `kb`, `adr new`, and the scope/finish/migrate preflights — they reach these on their own; nothing to set up. Full reference: the `@kvnwolf/dobby` README on npm.
