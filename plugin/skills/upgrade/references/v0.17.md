# v0.17.0 — per-task worker names, live status table, deeper lint areas

`/dobby:execute` now addresses each task's workers by their own name (`test-author-t<id>` / `implementor-t<id>` / `qa-t<id>`) instead of one shared `dobby:<role>` name across the whole plan, and prints a per-step status table after every worker verdict or fix round. `dobby spec lint` also relaxed and tightened `Affected areas` at the same time — `$param` route directories and paths nested arbitrarily deep are now accepted, while the task table's `#` column is now constrained to a legal identifier shape. See PR #55.

## Heads-up: worker Agent names changed — reload before your next execute

The old dispatch used `name: "dobby:<role>"`, which the Agent tool's `name` regex (`^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`) actually rejects — every first dispatch under that scheme failed with `InputValidationError`. The protocol now dispatches as `name: "test-author-t<id>"` / `"implementor-t<id>"` / `"qa-t<id>"` (`subagent_type` is unchanged, still `dobby:<role>`), and a task's three workers are dispatched once and reached by that same name across fix rounds until the task is terminal. Claude Code registers agent definitions at SESSION STARTUP: a session already open when you upgrade keeps the OLD `test-author` definition, which lacked `ToolSearch`/`SendMessage` — its test-authors cannot message anyone back until you run `/reload-plugins` (or start a fresh session on a host without it). This is the same failure shape ADR-0029 and the v0.14 note describe. If a consumer's `CLAUDE.md` or a custom skill hardcodes a worker Agent NAME (not `subagent_type`) of the old `dobby:<role>` form, update it.

## Rules that can go red: `dobby spec lint` now validates the task table's `#` column

Each task id must now match `[A-Za-z0-9][A-Za-z0-9_-]{0,20}` — it becomes part of the worker's Agent name (`<role>-t<id>`), so an illegal id would produce an illegal name at dispatch time. A spec whose `#` cells carry paths, spaces, or long labels now fails lint on the next `/dobby:spec`; renumber the tasks `1`, `2`, `3`… before it will pass.

## Relaxed, not breaking: `Affected areas` accepts `$param` routes and deeper paths

`AREA_PATH_SHAPE` previously excluded `$`, so a TanStack `$param` route directory wasn't recognized as a real path, and an area was accepted only when its direct parent already existed on disk — a module created two or more levels deep, or nested under a directory an earlier task creates, was rejected. Both are fixed: `$` is now a legal path character, and the existence check walks up to the nearest existing ancestor below the repo root. Specs that named whole directories as a workaround for this can now be narrowed to individual files; `task-decomposition.md` recommends file-level areas from the first draft.

## New behaviour in `/dobby:execute` (no action needed)

The Architect now prints a per-step status table (one row per task, one emoji per step: ⚪ 🔄 ❌ ✅ —) after every worker verdict and every fix round. Fix rounds close peer-to-peer: the fixer messages the reporter back by name with the round number, and a corrected test contract always returns through the implementor's own Exit gate before QA resumes — QA never runs the suite, so a test-contract fix can't reach `done` without passing through the mechanical gate first.

## Upgrade steps

1. `bun update @kvnwolf/dobby` in each consumer repo.
2. Restart the Claude Code session (or `/reload-plugins`) before your next `/dobby:execute` — the `test-author` agent's `tools:` frontmatter changed, and Claude Code registers agent tool access at session startup.
3. Run `bunx dobby spec lint` on any live `STATE.md`; renumber any `#` cells it now rejects.
4. Update any consumer doc or custom skill that hardcodes a worker Agent NAME of the old `dobby:<role>` form (subagent types are unaffected).
