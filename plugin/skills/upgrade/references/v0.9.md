# v0.9.0 — the uniform gate cache

## Heads-up: green checks can now answer from cache

`dobby check` (and `ship`'s in-process gate) now records a full green run keyed on a content hash of the non-inert tree, and later runs whose code didn't change skip every inferred step in under a second with an explicit note — `gate skipped: inputs unchanged since last green (<hash> @ <time>)`. Nothing to configure; the first full gate after the upgrade runs normally and records. What to know:

- Docs/prose-only changes (`**/*.md` outside fixture dirs, `docs/**`, `.claude/**`) never invalidate — that's the whole point.
- `checks[]` extras still run on every hit (they may read files the hash doesn't cover).
- `dobby check --no-cache` forces a full run (and still records on green). Red is never cached.
- Ship's `--json` payload gains `gateNote` (the hit line, or null when the gate really ran).
- Repos with checked-out submodules or tracked symlinks get NO cache (conservatively unkeyable — full run always, never a stale green).
- Known blind spot: gitignored env files (`.env.local`) are invisible to the key; use `--no-cache` after editing one if your tests read it.
