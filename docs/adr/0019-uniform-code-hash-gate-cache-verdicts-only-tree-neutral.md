# 0019. Uniform code-hash gate cache, verdicts-only, tree-neutral

`dobby check` re-ran the full gate on every invocation — a docs-only commit paid ~9 minutes of spawn-heavy vitest — so the gate gained a cache; the design deliberately rejects turborepo's per-task input scoping in favor of ONE uniform content hash of the non-inert tree, records verdicts only (never outputs, never red), and forbids cache bookkeeping from touching any versioned file.

## The decision, in three parts

1. **Uniform scoping, not per-tool.** Every gate step shares one key: the sha256 over the sorted (path, blob-oid) pairs of the whole working tree minus the **inert set** (`**/*.md` outside fixture dirs, `docs/**`, `.claude/**`), enumerated index-neutrally (`git ls-files -c -o --exclude-standard` + `git hash-object --stdin-paths` — untracked-but-unignored files count, per ADR-0017's poisoning invariant, without ever staging). Per-tool positive scopes (biome's lintable set, tsc's tsconfig closure) were rejected: override-by-presence (ADR-0015) makes a consumer's config a TOTAL override dobby cannot introspect, so honest per-tool scopes would require parsing arbitrary consumer configs and tracking each tool's discovery semantics across versions — an open-ended correctness surface — while the actual pain (prose/docs commits paying the full suite) is fully solved by the uniform hash. The trade: a `.css` edit re-runs tsc (harmless), in exchange for zero config introspection and one scoping rule to reason about.
2. **All-or-nothing green recording, LRU of 5.** A hash is recorded only when the FULL gate (no selective flags, no file args) exits 0; a hit skips every inferred step but still runs `checks[]` extras (they may read inert files no hash covers). Per-step green marks were rejected: with a shared key they help almost never (fixing a red changes the hash), and they'd need a special build→conventions rule to avoid recording a conventions-green proven against a red build's output. Red is never cached; selective runs consult but never record; `--no-cache` skips the consult and still records. The last five green hashes are kept (branch switches and reverts re-hit), invalidated wholesale by a dobby version or config-hash change. Every hit is EXPLICIT — a "gate skipped: inputs unchanged since last green (…)" note in check output and ship's `gateNote` payload field — because ADR-0017's founding incident was a misread gate, and a cached green indistinguishable from a run green would be a new way to misread one.
3. **Cache bookkeeping never touches a versioned file.** The first implementation wrote `.dobby/` into the project's `.gitignore` at record time; the wrap smoke test caught the consequence — a GREEN check dirtied the tree, and release's clean-tree preflight (plus the scope/finish preflights and the pre-push backstop, which would have mutated versioned files during a `git push`) refused mid-ceremony. The ignore guarantee now lives in `.git/info/exclude` (resolved via `git rev-parse --git-path` so linked worktrees share the common copy): local, unversioned, honored by the same ignore machinery. A `dobby check` leaves the working tree byte-for-byte as it found it; mutating `.gitignore` remains the privilege of flows that stage and commit (ship, onboard).

## Consequences

- Docs/skills/plan commits gate in well under a second (measured: 0.125s vs ~9 min on this repo) with the guarantee intact: identical non-inert inputs ⇒ identical verdict, the same property the whole-tree backstop cache already relied on.
- The cache file is additive: ship's flat 5-field record (the backstop fast-path contract, read by `hook-install.ts`'s deliberately independent reader) is byte-compatible; `greenInputs` rides alongside, owned by the shared `gate-cache.ts` module — the third `configHash` duplication was the documented extraction trigger.
- Known v1 blind spots, accepted: gitignored env files (`.env.local`) are invisible to the key though vitest presets load them, and a hand-mutated `node_modules` under an unchanged lockfile is equally invisible — the same blindness the pre-existing whole-tree cache had. Remedy in both cases: `dobby check --no-cache`.
- Per-tool scoping remains a possible v2 on top of this design (the uniform key can become the fallback tier), should a real workload ever need it.
