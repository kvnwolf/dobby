# 0018. Unified release by adapters

**Status:** accepted

Two project release skills (dobby's npm flow, mad-eye's homebrew-cask flow) carried a byte-near-identical spine — preflight, bump inference, lockstep manifests, changelog range, publish-gated tag+push, GitHub release, smoke — re-derived by an LLM on every release; the v0.5.1 incident (hardcoded indentation, no gate, misread output) proved that spine belongs in code. `dobby release` mechanizes it ONCE with per-target **release adapters** (npm | homebrew-cask) behind one interface; the skill-dir-script alternative lost because a script can't be reused by other consumers and drifts per copy.

Contracts this establishes: the command is **config-gated** on `dobby.config.json#release` (the CLI's first presence-gated command — no capability signal exists for "publishable"); human decisions pause via **needsDecision** (exit + JSON naming the decision; the skill asks and re-invokes with `--bump`) and the run stops at **needsNotes** so release notes are always MODEL-authored (rich, never a mechanical commit list) and delivered via `--notes-file`; manifests are bumped with detected indentation (the v0.5.1 root cause closed); CI-green is asserted in code against HEAD's sha. Notarization is optional per adapter (`release.notaryProfile`), credentialed ONLY through macOS keychain profiles — never env vars (mirrors mad-eye's ADR 0005). Trade-offs accepted: `gh`/`npm`/`xcrun` join the CLI's bare system tools (stub-bin tested), and a release can no longer run from a worktree (main-checkout preflight, per ADR-0008). Both project skills are absorbed by the thin `/dobby:release` plugin skill, which keeps only the gates and the notes authorship.
